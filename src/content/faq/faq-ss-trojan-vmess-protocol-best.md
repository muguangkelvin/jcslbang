在挑选科学上网机场或自建 VPS 节点时，我们经常会看到 **Shadowsocks (SS)、Trojan、VMess (V2Ray)** 这三个最经典、普及率最高的加密代理协议。

到底这三大传统协议有什么技术区别？**在防封锁稳定性、传输速度与 CPU 耗电上，哪一个才是综合表现最好的选择？** 本文为你进行技术拆解。

---

## 三大传统协议底层伪装原理对比

```mermaid
flowchart TD
    A[加密协议伪装路线] --> B[Shadowsocks: 对称加密对称混淆 -> 流量特征明显]
    A --> C[VMess: 自定义头部 + 多重加密 -> 复杂度高, 开销大]
    A --> D[Trojan: 模仿标准 HTTPS 网站 (TLS 443) -> 极高隐蔽性]
```

### 1. Shadowsocks (SS)
- **原理**：采用 AEAD 算法对数据包进行对称加密。
- **现状**：原版 Shadowsocks 的流量特征早已被 GFW 防火墙熟练掌握。目前仅在配合 **BGP 中转 / IPLC 专线**（数据包不通过公网出口海缆）时依然极其高效稳定；若在公网直连 VPS 上使用，IP 极易被墙。

### 2. VMess (V2Ray 内核首创)
- **原理**：基于时间戳与自定义头部的高安全代理协议，支持 WebSocket (WS) + TLS 伪装。
- **现状**：安全性高，非常适合公网搭建。缺点是握手过程较为繁琐，增加了额外的网络延迟，且在高并发下对 VPS 和手机 CPU 资源消耗较大。

### 3. Trojan (特洛伊木马协议)
- **原理**：放弃自定义加密特征，**直接伪装成互联网上最普遍的 HTTPS 网站流量**。数据包走标准的 443 端口与 TLS 证书握手。
- **现状**：GFW 很难将 Trojan 流量与正常的淘宝、百度 HTTPS 访问区分开来。在公网直连环境下，Trojan 的抗封锁性与速度显著优于原版 SS 和 VMess。

## 协议综合性能横向测评表

| 评测维度 | Shadowsocks (SS) | VMess (+WS+TLS) | Trojan (TLS 443) |
| :--- | :--- | :--- | :--- |
| **公网直连抗封锁能力** | 较差 (易被主动探测) | 优秀 (较安全) | **极佳 (伪装成真实网站)** |
| **专线/中转环境表现** | **极佳 (开销极小, 速度最快)** | 良好 (开销略大) | 良好 |
| **握手延迟跳动** | **最低** | 较高 (多层握手) | 中等 |
| **手机端 CPU 耗电量** | **极低** | 较高 | 较低 |
| **推荐使用场景** | IPLC 专线 / BGP 机场 | 备用节点 / 网页伪装 VPS | 公网直连 / 高品质中转 |

## 代理协议选型常见问题 (FAQ)

### Q1：为什么很多 IPLC 顶级专线机场依然大量使用 Shadowsocks 协议？
因为 IPLC 专线的数据在内网传输，根本不需要经过防火墙的检测。在 0 丢包的内网中，Shadowsocks 的加解密开销最小、延迟最低，能发挥出物理光纤的最大吞吐性能。

### Q2：现在还有必要使用 VMess 协议吗？
在公网直连自建节点时，VMess 已经被更新、更轻量的 **VLESS Reality** 协议超越；但在社区规则兼容性和旧版路由器插件中，VMess 依然具有极强的兼容性。

## 三大协议选型总结

总结协议挑选口诀：**“内网专线机场选 Shadowsocks 速度最快；公网直连 VPS 选 Trojan 伪装最稳；旧设备兼容选 VMess”**。根据你所使用的线路类型选择相匹配的协议，才能兼顾速度与安全。
